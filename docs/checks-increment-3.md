# Контрольная карта третьего инкремента

Основание: [задание](https://github.com/olgmina/SWEngineering-technics.github.io/blob/gh-pages/Labs/prTask_GraphEditor.md),
включая заключительное дополнение о независимом обходе и Builder для JSON/SVG.
Идентификаторы ниже отсылают к заданию; сценарии сформулированы для этой
реализации. Таблица описывает необходимое покрытие и не заменяет отчёт
конкретного запуска тестов.

Основные тестовые классы в `src/test/java/org/example/graphiceditor/`:
`model/DrawingTest`, `history/DrawingHistoryTest`, `model/EditorSettingsTest`,
`controller/DrawingSelectionTest`, `io/DrawingExporterTest`,
`io/ProjectFilesTest`, `io/PngProjectIOTest`, `ui/Increment3AcceptanceTest`
и `ui/PngProjectAcceptanceTest`. Их сценарии сопоставлены ниже; наличие
класса ещё не означает успешного выполнения теста.

## История действий

| Требования / проверки | Проверяемый сценарий реализации |
|---|---|
| FR-3.5; T3-05, T3-21 | Создать объект, затем Undo: восстановлен снимок до операции |
| FR-3.6; T3-06, T3-22 | После Undo выполнить Redo: восстановлен снимок после операции |
| T3-23 | Создать два объекта отдельными операциями; Undo отменяет только вторую |
| T3-24 | Изменить оформление, геометрию или фон; Undo восстанавливает прежнее значение |
| T3-25 | После Undo выполнить новую правку; предыдущее продолжение Redo недоступно |
| Дополнительно | Штрих и перетаскивание группируются по жестам; пустая операция не создаёт запись; отмена жеста не портит историю |

История использует `Drawing.Snapshot` и ограничена 100 завершёнными
операциями. Пустые стеки, сброс на открытии/новом документе и отсутствие
истории в сохранённом файле проверяются отдельно от восстановления рисунка.

## Архитектурное дополнение

| Требование | Проверяемое устройство |
|---|---|
| FR-3.9.1 | `DrawingExporter` содержит один обход; модель не знает синтаксиса PNG/JSON/SVG |
| FR-3.10.1 | `JsonDrawingBuilder` создаёт `JsonFile`, `SvgDrawingBuilder` — `SvgFile`; продукты не наследуются от общего предметного типа |
| FR-3.10.2 | Тестовый builder фиксирует start → каждый pixel → каждый shape → finish; растровый слой предшествует векторному |

Здесь учитывается позднее дополнение методички: обязательные JSON/SVG и Builder.
Пошаговая передача объектов не отменяет ограничений размера файлов и памяти
для завершённого результата конкретного формата.

## Приёмка и регрессии

| Проверки | Сценарий интерфейса |
|---|---|
| AT3-01 | Нарисовать кистями и создать несколько оформленных полигонов |
| AT3-02 | Режим «Выбор»: выбрать, переместить и удалить объект; проверить выделение |
| AT3-03, AT3-04 | Несколько действий → Undo → Redo; проверить рисунок и доступность команд |
| AT3-05 | Изменить фон и настройку привязки; проверить поведение на холсте |
| AT3-06, AT3-07 | Сохранить в выбранном формате, открыть в новом документе, продолжить редактирование |
| AT3-08 | Сохранить полигон со всеми декораторами; после открытия поменять цвет и переместить вершину |
| AT3-09 | Открыть ошибочный файл; увидеть сообщение и сохранить рабочий рисунок |
| R3-01–R3-04 | Повторить проверки точек, круга, квадрата и фабрик первого инкремента |
| R3-05–R3-09 | Повторить создание полигонов и все сочетания/порядки декораторов второго инкремента |
| R3-10 | Проверить существующие подсказки инструментов |

Автотесты JavaFX создают события и проверяют модель и пиксели холста.
Это не равнозначно проверке физических жестов конкретного устройства.
Нативные диалоги ОС и подтверждения требуют отдельной проверки, если тест
использует методы сохранения/открытия напрямую.

## Выпуск

```sh
./mvnw -DexcludedGroups= clean verify
```

Перед итоговым Release проверяются полный набор тестов всех трёх
инкрементов, версия 1.0.1 в коде и документации, README с управлением
и форматами, CHANGELOG, актуальные диаграммы в
[architecture-v3.md](architecture-v3.md), состояние Git и содержимое выпуска.
Результат текущего запуска указывается после фактической проверки;
исторические результаты версии 0.2.0 не подменяют проверку 1.0.1.

Проверка версии 1.0.1 от 2026-10-29: `./mvnw -q -DexcludedGroups= clean verify` —
**188 тестов, 0 сбоев, 0 ошибок, 0 пропусков**. Проверены три оставшихся
формата PNG, JSON и SVG, отклонение неподдерживаемого бинарного файла,
Undo/Redo и регрессии предыдущих инкрементов.
